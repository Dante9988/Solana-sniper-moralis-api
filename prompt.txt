We are not building automatic trading. We are not changing wallets, private keys, or enabling buy/sell execution.

## Core objective

Create a separate intelligence layer that receives a normalized token event from listeners and researches the token before creating an actionable intelligence record.

Target flow:

```text
Pump.fun / PumpSwap / migration listener
  → normalized TokenDiscoveryEvent
  → token intelligence orchestrator
  → deterministic metadata + market + safety research
  → parallel specialized research tasks where useful
  → AI synthesis with evidence
  → PostgreSQL source-of-truth persistence
  → Chroma semantic index for RAG
  → later: notification channels and human review
```

The listeners are event sources only. They should not contain all analysis logic.

## Agent architecture

Create a service called `TokenIntelligenceOrchestrator`.

It is the lead intelligence agent and may invoke focused worker modules/subagents only when needed:

1. `metadata-researcher`

   * Fetch on-chain mint data.
   * Fetch name, symbol, URI, image, creator/deployer.
   * Resolve Pump.fun and PumpSwap state.
   * Extract website, X, Telegram, Discord and other socials.
   * Identify missing, malformed, copied, or suspicious metadata.

2. `market-researcher`

   * Pull price, market cap/FDV, liquidity, volume, trades, pools and age.
   * Use existing project services where possible.
   * Store source timestamps and distinguish unavailable from verified values.

3. `safety-researcher`

   * Check mint authority, freeze authority, token standard, liquidity status, holder concentration, creator holdings, developer wallet history, RugCheck, SolSniffer and known risk flags.
   * Never claim “safe”; return evidence, uncertainty, and risk factors.

4. `bundle-sniper-researcher`

   * Reuse existing sniper/bundle/trench services where available.
   * Determine likely bundled buys, sniper share, related early wallets, creator-linked wallets, and concentration.
   * Return raw evidence and confidence—not unsupported labels.

5. `social-researcher`

   * Evaluate extracted socials and links.
   * Detect presence/absence, consistency between token metadata and public accounts, account age/verification where data is available, and obvious impersonation signals.
   * Do not scrape restricted platforms or bypass access controls.

6. `ai-synthesis-agent`

   * Uses local Ollama through a provider abstraction.
   * Receives only structured research outputs.
   * Produces schema-validated JSON, never free-form text controlling execution.
   * Explains the token’s narrative, evidence, risk factors, missing data, and confidence.
   * Must not make a “buy” decision.

Use deterministic analysis before AI. The LLM is for context synthesis, ambiguity detection, and explanation—not for deciding facts that can be validated through on-chain or API data.

## RAG / Chroma requirement

Use PostgreSQL as the source of truth.

Add Chroma only as a semantic-search projection. Index:

* normalized token report
* token name/symbol/narrative
* social findings
* safety and bundle findings
* AI assessment
* source event ID, mint, source, timestamps, risk level and confidence as metadata

This must allow future questions such as:

* “Show tokens with a similar narrative to this one.”
* “Have we seen this creator, website, Telegram, or wallet before?”
* “Which migrations had high bundled-wallet risk?”
* “What signals appeared before tokens that later performed well or rugged?”

Do not allow an AI agent to write directly to PostgreSQL or Chroma. It must call controlled application services.

## Security boundaries

These are mandatory:

* Do not enable or add automated buying, selling, swaps, signing, wallet funding, or private-key access.
* Do not modify existing wallet files or print `.env` contents.
* Do not make AI output sufficient to execute a transaction.
* Add an explicit execution guard that always fails closed.
* Preserve current simulation/disabled behavior.
* Do not describe any token as guaranteed safe, legitimate, profitable, or a buy.
* Record data source, timestamp, missing fields, errors, and confidence for every report.
